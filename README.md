# Новостной сайт на Laravel

Учебный проект по дисциплине "Серверная веб-разработка".
Московский политехнический университет, группа 257-321, Ледовских Владислав.

## Зачем этот проект

Это сайт, на котором можно публиковать новости и обсуждать их в комментариях.
По сути он повторяет то, что делает любой новостной портал: показывает список
материалов, открывает каждый из них отдельной страницей, позволяет оставить отзыв
и следит за тем, чтобы в обсуждении не было мусора.

Главное отличие от сайта-визитки в том, что содержимое здесь не записано в файлах
страниц. Новости лежат в базе данных, а страницы собираются сервером в тот момент,
когда их открывает посетитель. Поэтому добавить материал можно через обычную форму
на сайте, и он сразу появится в списке, без правки кода и без выкладки файлов
на сервер.

Проект писался не как набор отдельных лабораторных, а как одно приложение, которое
постепенно обрастало возможностями: сначала появился макет страниц, затем новости
переехали в базу, потом добавились регистрация, роли, комментарии с проверкой,
почтовые уведомления, очередь задач, кэширование и программный интерфейс. Каждый
следующий этап дополнял предыдущий, поэтому весь код живёт в одном приложении
и связан между собой.

## Что умеет сайт

Посетителю без учётной записи доступны главная страница со списком новостей,
постраничная навигация, страница отдельной новости с изображением и текстом,
а также страницы "О нас" и "Контакты". В обсуждении он видит только те
комментарии, которые уже проверил модератор.

Зарегистрированный пользователь получает роль "читатель". Он может оставлять
комментарии, но его отзыв появляется на странице не сразу: сначала он попадает
в очередь на проверку. Кроме того, читатель получает уведомления о новых
материалах - в шапке сайта есть значок с количеством непрочитанных новостей
и выпадающий список с их названиями.

Модератор отвечает за содержимое сайта. Он создаёт, редактирует и удаляет новости,
принимает или отклоняет комментарии, а также раз в день получает на почту сводку:
сколько новостей прочитали и сколько комментариев добавили. Пункты управления
видны в меню только модератору, остальные пользователи их не видят и не могут
открыть даже по прямой ссылке.

Отдельно стоит упомянуть две вещи, которые не видны на первый взгляд. Первая -
если модератор публикует новость, пока кто-то читает сайт, у этого посетителя
без перезагрузки страницы всплывает уведомление о свежем материале. Вторая -
у сайта есть программный интерфейс (REST API), который отдаёт те же данные
в формате JSON, поэтому новости можно получать не только через браузер,
но и из другого приложения.

**Создать файл базы данных.** Проект использует SQLite - базу, которая хранится
в одном файле и не требует установки отдельного сервера. Файл нужно создать
пустым, таблицы появятся в нём на следующем шаге.

```bash
touch database/database.sqlite
```

**Создать таблицы и наполнить их данными.** Команда выполняет миграции -
описания структуры базы, а затем запускает сидер, который создаёт роли,
трёх пользователей, шестнадцать новостей и несколько комментариев. Так на сайте
сразу есть что посмотреть, и не приходится вручную добавлять материалы.

```bash
php artisan migrate --seed
```

**Запустить сайт.**

```bash
php artisan serve
```

После этого сайт открывается по адресу <http://127.0.0.1:8000>. Остановить
сервер можно сочетанием клавиш `Ctrl+C` в том же терминале. Если нужно начать
с чистого листа, команда `php artisan migrate:fresh --seed` удалит все таблицы
и создаст их заново вместе с демонстрационными данными.

## Кто может что делать

Все тестовые пользователи создаются автоматически при наполнении базы, пароль
у них одинаковый - `password`. Различаются они ролью, и именно от роли зависит,
какие кнопки человек увидит на сайте.

| Почта | Роль | Что доступно |
|-------|------|--------------|
| `moderator@example.com` | модератор | всё: публикация и правка новостей, модерация комментариев, статистика на почту |
| `reader@example.com` | читатель | просмотр новостей, комментарии, уведомления о новых материалах |
| `test@example.com` | читатель | то же самое, аккаунт остался с раннего этапа работы |

Новый пользователь, зарегистрировавшийся через форму, тоже получает роль
"читатель". Повысить его до модератора можно только в базе данных - на сайте
такой возможности нет, и это сделано намеренно, чтобы любой посетитель
не мог выдать себе права.

## Что нужно запускать дополнительно

Сам сайт работает и без этих процессов: новости читаются, формы отправляются,
комментарии сохраняются. Но часть возможностей при этом молчит, поэтому для
полной демонстрации нужно открыть ещё два-три терминала.

**Очередь задач.** Письмо модератору о новой новости не отправляется прямо
во время запроса: сайт лишь кладёт задание в таблицу `jobs`, а отправляет его
отдельный процесс. Так пользователь не ждёт, пока почтовый сервер ответит.
Если процесс не запущен, задания просто копятся в таблице.

```bash
php artisan queue:work
```

**Сервер широковещания.** Всплывающее уведомление о новой новости приходит
по WebSocket-каналу, который обслуживает Laravel Reverb. Без него сайт
работает как обычно, но всплывающих сообщений не будет.

```bash
php artisan reverb:start
```

**Планировщик.** Задача ежедневной статистики запускается по расписанию.
В реальной эксплуатации её вызывает системный cron раз в минуту, а на учебной
машине проще держать отдельный процесс, который проверяет расписание сам.

```bash
php artisan schedule:work
```

Проверить, что всё работает, можно так: войдите как модератор, создайте новость -
в терминале с очередью появится строка об отправке письма, в шапке сайта
у читателя появится уведомление, а в журнале `storage/logs/laravel.log` будет
видно текст письма, потому что в учебной конфигурации письма не отправляются
по-настоящему, а записываются в файл.

## Как устроен проект

Приложение построено по схеме MVC, которую использует Laravel: маршрут решает,
какой контроллер обработает запрос, контроллер обращается к модели за данными
и передаёт их в шаблон, а шаблон формирует HTML-страницу. Такое разделение удобно
тем, что правка оформления не затрагивает логику, а изменение правил работы
с данными не ломает вёрстку.

| Что | Где лежит | Зачем нужно |
|-----|-----------|-------------|
| Маршруты | `routes/web.php`, `routes/api.php` | список адресов сайта: какой адрес какой метод контроллера вызывает |
| Контроллеры | `app/Http/Controllers` | принимают запрос, проверяют права и данные, возвращают страницу или JSON |
| Модели | `app/Models` | описывают таблицы базы и связи между ними |
| Шаблоны | `resources/views` | HTML-страницы на шаблонизаторе Blade |
| Общий макет | `resources/views/layouts/app.blade.php` | шапка, меню, подвал и подключение стилей - всё, что повторяется на каждой странице |
| Миграции | `database/migrations` | описание структуры базы в виде PHP-файлов |
| Наполнение базы | `database/seeders`, `database/factories` | демонстрационные данные и генератор случайных новостей |
| Права доступа | `app/Policies`, `app/Providers/AuthServiceProvider.php` | правила вида "модератору можно, читателю нельзя" |
| Посредники | `app/Http/Middleware`, `bootstrap/app.php` | проверки, которые выполняются до контроллера, например учёт просмотров |
| Фоновые задания | `app/Jobs`, `app/Events`, `app/Notifications` | отправка письма, оповещение открытых вкладок, уведомления читателям |
| Вспомогательные классы | `app/Support` | кэш новостей и общий набор действий после публикации материала |
| Команды и расписание | `app/Console/Commands`, `routes/console.php` | ежедневная статистика и её запуск по времени |

Отдельно стоит сказать про папку `public`. В ней лежат точка входа сайта, стили,
изображения новостей и готовые файлы фронтенда. Именно эта папка открыта
для посетителей, всё остальное - код приложения - снаружи недоступно.

## Как устроена база данных

База состоит из шести основных таблиц, и каждая отвечает за свою сущность.
Таблица `articles` хранит новости: заголовок, краткое описание, текст, дату
публикации и имена файлов с изображениями. Хранятся именно имена, а не сами
картинки, потому что файлы удобнее держать в папке `public/images` - веб-сервер
отдаёт их напрямую, не нагружая базу.

Таблица `users` содержит зарегистрированных пользователей, а таблица `roles` -
две роли, модератора и читателя. Связь между ними простая: у каждого пользователя
есть ссылка на одну роль, поэтому права проверяются по одному полю.

Таблица `comments` связывает комментарий с новостью и с пользователем. Если
новость удалить, её комментарии удалятся автоматически - за это отвечает каскадное
удаление на уровне базы. Поле `is_approved` показывает, прошёл ли комментарий
проверку: пока оно пустое, комментарий видит только модератор.

Таблица `article_views` фиксирует каждое открытие страницы новости: адрес,
идентификатор материала, адрес посетителя и его браузер. Эти записи нужны
для ежедневной статистики - по ним считается, какие новости читают чаще всего.

Таблица `notifications` хранит уведомления читателей о новых материалах.
Пока поле `read_at` пустое, уведомление считается непрочитанным и учитывается
в счётчике на панели навигации.

Кроме них в базе есть служебные таблицы, которые создаёт сам фреймворк:
`jobs` и `failed_jobs` для очереди, `cache` для кэша, `sessions` для сессий,
`personal_access_tokens` для токенов входа, `migrations` для учёта выполненных
миграций. Их не нужно трогать вручную.

## Проверка REST API

Программный интерфейс расположен по адресам с префиксом `/api` и отвечает
в формате JSON. Список новостей можно получить без авторизации - достаточно
открыть адрес в браузере или выполнить команду:

```bash
curl "http://127.0.0.1:8000/api/articles?per_page=3"
```

Для операций, изменяющих данные, нужен токен. Он выдаётся при входе:

```bash
curl -X POST http://127.0.0.1:8000/api/login \
  -H "Accept: application/json" \
  -d "email=moderator@example.com&password=password"
```

Полученный токен передаётся в заголовке `Authorization` при создании новости:

```bash
curl -X POST http://127.0.0.1:8000/api/articles \
  -H "Accept: application/json" \
  -H "Authorization: Bearer <токен>" \
  -d "title=Проверка API&content=Текст новости для проверки API&published_at=2026-11-15&preview_image=preview.jpg&full_image=full.jpeg"
```

Если токен не передан, сервер ответит ошибкой 401, а если передан токен читателя -
ошибкой 403 с объяснением, что управлять новостями может только модератор.

## Если что-то не работает

**Сайт пишет, что не найдена папка vendor.** Не установлены зависимости,
выполните `composer install`.

**Ошибка 500 и сообщение про отсутствующую таблицу.** Не выполнены миграции,
выполните `php artisan migrate --seed`.

**Письма не приходят на почту.** Так и должно быть: в учебной настройке
`MAIL_MAILER=log`, поэтому письма не отправляются, а записываются в файл
`storage/logs/laravel.log`. Чтобы отправлять настоящие письма, нужно указать
в `.env` данные почтового сервера и поставить `MAIL_MAILER=smtp`.

**Не появляется всплывающее уведомление о новой новости.** Проверьте, что
запущен `php artisan reverb:start` и что страница открыта в браузере, который
поддерживает WebSocket. Если менялись файлы в `resources/js`, фронтенд нужно
пересобрать командой `npm run build`.

**Забыл пароль от тестового аккаунта.** Пароль у всех демонстрационных
пользователей одинаковый - `password`. Если база испорчена, проще пересоздать
её командой `php artisan migrate:fresh --seed`.

## Состав репозитория

```
app/                  код приложения: контроллеры, модели, политики, задания
bootstrap/app.php     настройка приложения: посредники и обработка ошибок
config/               конфигурация Laravel
database/             миграции, фабрики, сидеры
docs/                 пояснительная записка
public/               точка входа, стили, изображения новостей, сборка фронтенда
resources/views/      шаблоны страниц и писем
resources/js/         компонент Vue для всплывающего уведомления
routes/               маршруты сайта, API и расписание задач
storage/logs/         журналы, сюда пишутся письма в учебном режиме
```

Проект написан на PHP 8.3 и новее (проверялся на 8.5) с использованием Laravel 13, шаблонизатора Blade,
базы SQLite, библиотеки Sanctum для токенов и Vite с Vue 3 для интерактивной
части. Всё перечисленное - стандартный набор инструментов современной
веб-разработки, поэтому полученные навыки применимы не только в учебных задачах.
